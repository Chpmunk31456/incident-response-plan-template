# AI Assistant Context Recovery Procedure

## 1. Purpose

Establish a repeatable process for recovering project context,
previous decisions, verified facts, and known corrections.

Prevent repeated errors caused by incomplete or outdated context.

## 2. Recovery Triggers

Use this procedure when:

- Beginning a new conversation involving an existing project.
- Resuming work after a long interruption.
- The user reports that information was forgotten.
- Previously rejected recommendations reappear.
- Instructions conflict with earlier decisions.
- A task requires information from previous conversations.
- The assistant cannot verify whether work was completed.

## 3. Recovery Workflow

### Step 1: Identify the Project

Determine which project or task is being continued.

### Step 2: Retrieve Available Context

Consult:

1. Current conversation and user instructions.
2. Relevant ChatGPT memory, when available.
3. Master Memory Index.
4. Decision Register.
5. Memory and Error Register.
6. Relevant project-specific records.
7. Authoritative external sources when current verification is needed.

Do not assume repository documents have been retrieved
unless their contents have actually been accessed.

### Step 3: Reconstruct the Current State

Identify:

- Current objectives.
- Latest verified decisions.
- Completed work.
- Outstanding work.
- Previous mistakes.
- Active corrective actions.
- Unresolved questions.

### Step 4: Resolve Conflicts

When information conflicts:

- Prefer the user's latest explicit instructions.
- Review dated evidence.
- Identify superseded decisions.
- Distinguish confirmed facts from assumptions.
- Ask for clarification when necessary.

### Step 5: Verify Before Acting

Apply the Verification Checklist.

For employment research, verify:

- Official employer application pages.
- Current vacancy status.
- Work location eligibility.
- Employment structure.
- Mandatory qualifications.
- Previous applications and rejections.
- Duplicate recommendations.

### Step 6: Continue the Task

Resume work using verified information.

Do not repeat completed tasks unnecessarily.

### Step 7: Record Corrections

When a significant mistake occurs:

1. Document the error.
2. Identify its root cause.
3. Define corrective action.
4. Assign responsibility.
5. Establish a verification method.
6. Record the result.

## 4. Recovery Status

Use these classifications:

- RECOVERED: Required context retrieved and verified.
- PARTIAL: Some relevant information remains unavailable.
- UNVERIFIED: Information exists but has not been validated.
- BLOCKED: Essential information cannot be recovered.

## 5. Completion Requirements

Before declaring recovery complete:

- [ ] Project identified.
- [ ] Relevant context retrieved.
- [ ] Active decisions reviewed.
- [ ] Known errors checked.
- [ ] Current information verified.
- [ ] Outstanding issues identified.
- [ ] Recovery status documented.

## 6. Confidentiality

Do not publish private employment records,
medical information, credentials, personal identifiers,
or confidential security evidence.

Use access-controlled systems for sensitive records.

## 7. Technical Limitations

GitHub is an external reference repository.

It does not automatically update ChatGPT memory.

The assistant must have access to the repository and
retrieve the relevant documents before using them.

This procedure improves continuity but cannot guarantee
perfect recall or prevent every error.
